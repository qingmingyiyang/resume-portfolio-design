# 招聘表单填写

## 在线简历表单填写规范

实际填写招聘表单时，按该表单字段和限制处理。仅准备离线可复制资料时，无需先找到具体招聘页面，按[简历制作要点](resume-playbook.md)组织已知内容。

### 照片上传入口

检查实际表单是否有照片上传入口及其必填状态，按页面要求处理，不推定所有招聘表单都需要照片。

**操作要求**：
1. 实际填表时检查页面或用户提供的字段中是否存在照片入口；离线资料沿用用户已确认照片，不强制索取新照片
2. 如果存在，必须在填写指南中单独列出"个人形象"或"个人照片"板块
3. 照片格式、背景和尺寸以实际表单要求为准；需要建议时提供清晰、自然的证件照方案
4. 只有照片为必填且当前缺少可用照片时才提醒补充，不阻塞其他文字整理

### 表单字段完整性

在线表单的字段可能与标准简历不同，常见的易漏字段包括：
- **个人形象/个人照片**：image类型上传字段
- **实习时长/到岗时间**：下拉选择或文本输入
- **期望薪资/实习薪资**：文本输入
- **亲友在该公司任职**：是/否选择
- **项目经历**：部分表单有独立的项目经历板块，部分没有
- **作品/作品链接**：部分表单允许上传作品集附件或填写URL
- **自我评价/个人优势**：文本域，通常有字数限制

**操作要求**：在生成填写内容前，读取实际表单 DOM、截图或可用文本，识别本次要填写的字段后逐项生成；无需强制转换 Markdown，避免遗漏。

### 侧重建议与逐项填写内容（必须产出）

有实际JD及表单时据此提供文本；离线完整资料按通用字段整理。侧重建议与可复制正文分开，用户只要文字时仅交付文字。

**其一，侧重建议。** 基于JD匹配度分析，指出每个字段填写时应该往哪个方向侧重。例如实习经历板块，JD要求用户体验优化能力，则侧重建议为"将面试方法迭代重构为体验优化叙事，突出问题识别→方法调整→效果验证的闭环"。侧重建议不是泛泛而谈的"注意匹配"，而是针对每个字段的具体填写策略。

**其二，逐项填写内容。** 为每个字段生成可直接复制粘贴的具体文本。不允许只给方向不给文本，不允许只写"此处填写XXX"的占位符。已知字段提供可直接使用的文字；未知个人事实明确标记待补，不编造薪资、到岗时间、成绩等。提交或上传依照当前用户授权，准备文本不代表已提交。按实际任务选用以下字段：
- 基本信息：各字段的具体值和建议
- 个人形象：仅在相关时列出现有照片或实际上传要求
- 教育经历：学校、专业、时间、GPA/排名的填写方式
- 实习经历：按目标岗位表达的完整STAR描述（保留真实含义，不默认都改成产品语言）
- 项目经历：精选项目的完整描述
- 自我评价：针对目标岗位定制的完整文本
- 语言能力、获奖、技能等：具体勾选项和填写文本

**产出格式**：单字段修改直接交付该字段。完整填写稿保存为Markdown；需要完整可复制资料时另提供本地HTML，按[简历制作要点](resume-playbook.md)实现展开、字数与最小单元复制。Markdown文件名为`{用户姓名}-{目标岗位简称}-简历填写内容.md`，按表单板块分节，每节含字段表格和填写建议。


### 侧重建议的生成方法

侧重建议的生成遵循以下逻辑：

1. **按 JD 匹配**：将JD的每个核心要求与用户的每段经历进行匹配，标出强匹配、弱匹配、无匹配
2. **对强匹配项**：侧重建议为"突出呈现，作为该板块的主叙事"
3. **对弱匹配项**：侧重建议为"用可迁移能力重构，找到经历中的侧面来回应JD需求"
4. **对无匹配项**：说明可迁移的真实经验；必须回答的条件如实填写，不把未具备能力写成已具备
5. **对每个表单板块**：综合JD匹配矩阵，给出该板块应选择哪段经历、用哪种叙事角度、突出哪个侧面的具体策略
